  Reconcile-instead-of-rebuild is the fix if it matters in practice.

  throttle at `:661-674` only kicks in when fullscreen misses target FPS) — partly

- **MJPEG/preview JPEG encode on the renderer thread** (`ipc-handlers.ts:1229-1231`) — plan
  003 removes the redundant render; moving the encode to a worker (OffscreenCanvas) is the
  next step if preview cost still shows with many remote clients.

## Findings considered and rejected

- **Gating re-upload of unchanged pp/tiling/resolution uniforms**
  (`shader-renderer.ts:1341,1363-1372`, `mini-shader-renderer.ts:426-435`): ~10 cheap
  `gl.uniform*` calls/frame, no GPU stall; a missed dirty-flag site would freeze a visual
  effect live. Cost/benefit says no.
- **`prepareSharedState()` object literal + `applyABTiling` closure per fullscreen frame**
  (`fullscreen-renderer.ts:383-402, 1252-1260`): minor young-gen churn; fix only if touching
  that code anyway (noted in 005's maintenance notes).
- **Per-tile `SCISSOR_TEST` enable/disable + unconditional texture rebinds**
  (`tile-renderer.ts:306-307,359-373`): real but marginal GL-call churn; bundle into 004's
  follow-ups if ever, not standalone.
- **`remote-server.broadcast()` per-client stringify**: not a finding — it already
  stringifies once for all clients (`remote-server.ts:148`).
- **Grid thumbnail animation loop**: already exemplary (IntersectionObserver + 10 fps timer,
  hidden-gate) — no action.
- **Beat detector per-frame cost**: a few hundred simple operations/frame; negligible next to
  a 4K fragment shader.
